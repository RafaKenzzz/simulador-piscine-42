ex01 print_groups

Escreve uma linha de comando que mostra os grupos a que pertence o login guardado na variável de ambiente FT_USER.

mostrar soluçãoesconder solução

Passo a passo

  1. id -Gn "$FT_USER" mostra os nomes (-n) de todos os grupos (-G) do utilizador, separados por espaços.
  2. tr ' ' ',' troca cada espaço por uma vírgula.
  3. tr -d '\n' apaga a quebra de linha final, como mostra o exemplo.

Erros comuns

  • Esquecer o -n: aparecem os números dos grupos em vez dos nomes.
  • Deixar a quebra de linha no fim.
  • Escrever FT_USER=... dentro do script: a variável é definida por quem testa.

Casos limite que a moulinette testa

  • Um utilizador com um só grupo mostra só esse nome, sem vírgulas.
  • A ordem dos grupos é a que o id dá; não ordenes.

ex02 find_sh

Escreve uma linha de comando que procura, na pasta atual e em todas as subpastas, os ficheiros cujo nome termina em .sh.

mostrar soluçãoesconder solução

Passo a passo

  1. find . -type f -name '*.sh' encontra os ficheiros em qualquer subpasta.
  2. O primeiro sed apaga tudo até à última /, ficando só o nome do ficheiro.
  3. O segundo apaga o .sh do fim (o ponto vai escapado: \.).

Erros comuns

  • Cortar com cut -d '.' -f 1, que estraga nomes com mais pontos, como a.b.sh, e caminhos que começam por ./.
  • Esquecer as aspas em '*.sh': se houver um .sh na pasta atual, a shell expande o padrão antes do find.

Casos limite que a moulinette testa

  • Ficheiros em subpastas profundas aparecem só pelo nome.
  • Um ficheiro x.shx não termina em .sh e não aparece.

ex03 count_files

Escreve uma linha de comando que conta e mostra o número de ficheiros regulares e de pastas na pasta atual e em todas as subpastas.

mostrar soluçãoesconder solução

Passo a passo

  1. find . começa na pasta atual e inclui-a no resultado.
  2. \( -type f -o -type d \) fica só com ficheiros regulares e pastas.
  3. wc -l conta as linhas, uma por entrada.
  4. No macOS, o wc põe espaços antes do número; o tr -d ' ' apaga-os.

Erros comuns

  • Usar só find . | wc -l: também conta ligações simbólicas e outros tipos.
  • Usar ls -R, que mistura nomes, linhas vazias e cabeçalhos de pasta.

Casos limite que a moulinette testa

  • Uma pasta vazia dá 1 (a própria .).
  • Ficheiros escondidos também contam.

ex04 MAC

Escreve uma linha de comando que mostra os endereços MAC da tua máquina, cada um seguido de uma quebra de linha.

mostrar soluçãoesconder solução

Passo a passo

  1. O ifconfig mostra a configuração de rede. O endereço MAC está nas linhas que começam por ether.
  2. grep 'ether ' fica só com essas linhas.
  3. awk '{print $2}' mostra a segunda palavra da linha, que é o endereço.

Erros comuns

  • Usar cut -d ' ' -f 2: no Linux as linhas começam com espaços e o cut devolve uma coluna vazia. O awk ignora os espaços iniciais.
  • Esquecer o espaço em 'ether ', que também apanha outras linhas com «ether».

Casos limite que a moulinette testa

  • No macOS da 42 há várias interfaces: mostra todos os endereços, um por linha.
  • Em Linux sem ifconfig, o equivalente é ip link | awk '/link\/ether/ {print $2}'.

ex05 Can you create it?

Cria um ficheiro que contenha só 42, e mais NADA (nem quebra de linha).

mostrar soluçãoesconder solução

Passo a passo

  1. Dentro de plicas ('…') a shell não interpreta nada: nem $, nem *, nem \, nem ".
  2. A única coisa que não pode estar dentro de plicas é outra plica. Para a pôr, fecha-se a plica, escreve-se "'" (uma plica entre aspas) e abre-se outra vez.
  3. printf '42' escreve os dois caracteres sem quebra de linha. O echo acrescentaria uma e ficavas com 3 bytes.
  4. O chmod 614 acerta as permissões do exemplo (-rw---xr--); a data é opcional.

Erros comuns

  • Usar aspas em vez de plicas: o $* e o $? são substituídos pela shell.
  • Usar echo 42: o ficheiro fica com 3 bytes.
  • Criar o ficheiro com um nome parecido. Confirma com ls | cat -e.

Casos limite que a moulinette testa

  • O tamanho tem de ser exatamente 2 bytes.

ex06 Skip

Escreve uma linha de comando que mostra uma em cada duas linhas da saída de ls -l, a começar pela primeira.

mostrar soluçãoesconder solução

Passo a passo

  1. sed -n só imprime quando lhe mandam (p).
  2. Para cada linha, p imprime-a e n passa à seguinte sem a imprimir.
  3. Resultado: linhas 1, 3, 5, … A primeira linha é o total do ls -l, e conta.

Erros comuns

  • Começar na segunda linha (sed -n 'n;p').
  • Esquecer o -n: o sed imprime todas as linhas e ainda repete algumas.

Casos limite que a moulinette testa

  • Com um número par de linhas, a última não aparece; com um número ímpar, aparece.

ex07 r_dwssap

Escreve uma linha de comando que mostra a saída de cat /etc/passwd com estes passos, por esta ordem:

mostrar soluçãoesconder solução

Passo a passo

  1. grep -v '^#' apaga as linhas que começam por # (os comentários).
  2. sed -n 'n;p' salta uma linha e imprime a seguinte: fica com as linhas 2, 4, 6, …
  3. cut -d ':' -f 1 fica só com o login (a primeira coluna).
  4. rev escreve cada login ao contrário e sort -r ordena ao contrário.
  5. sed -n "${FT_LINE1},${FT_LINE2}p" fica com o intervalo pedido. As aspas são duplas para as variáveis serem substituídas.
  6. tr '\n' ',' junta tudo numa linha; o primeiro sed troca a última vírgula por um ponto e o segundo põe um espaço depois de cada vírgula.
  7. O tr -d '\n' final garante que não fica nenhuma quebra de linha (o sed do macOS acrescenta uma).

Erros comuns

  • Inverter a ordem dos passos: ordenar antes de escolher as linhas pares dá outro resultado.
  • Usar grep -v '#', que também apaga linhas com # no meio.
  • Usar plicas em "${FT_LINE1},${FT_LINE2}p": as variáveis não são substituídas.
  • Deixar , . ou ,. no fim por trocar as vírgulas pela ordem errada.

Casos limite que a moulinette testa

  • Com FT_LINE1 igual a FT_LINE2 sai um só login seguido de ..
  • Num /etc/passwd com menos linhas do que FT_LINE2, mostra até ao fim.

ex08 add_chelou

Escreve uma linha de comando que lê dois números das variáveis FT_NBR1 e FT_NBR2 e mostra a soma dos dois.

mostrar soluçãoesconder solução

Passo a passo

  1. As duas bases têm 5 símbolos, por isso os dois números são base 5. O passo 1 é traduzi-los para os algarismos 0–4.
  2. sed "s/'/0/g" troca as plicas por 0; tr '\\"?!' '1234' troca \, ", ? e ! por 1, 2, 3 e 4; tr 'mrdoc' '01234' traduz o segundo número.
  3. Fica algo como 10321201 + 14120222. O xargs echo 'obase=13; ibase=5;' junta-lhe as instruções para o bc.
  4. O obase vem antes do ibase: se viesse depois, o 13 seria lido em base 5.
  5. O bc faz a soma e escreve-a em base 13 com os algarismos 0–9 e A–C.
  6. O último tr traduz esses 13 algarismos para gtaio luSnemf.
  7. O echo "$FT_NBR1 + $FT_NBR2" vai entre aspas: o ? é um padrão da shell e, sem aspas, podia ser trocado por nomes de ficheiros da pasta.

Erros comuns

  • Pôr o ibase antes do obase.
  • Esquecer que o \ precisa de ser escapado dentro do tr.
  • Deixar o $FT_NBR1 sem aspas: numa pasta com ficheiros de um carácter, o ? é expandido.

Casos limite que a moulinette testa

  • Os dois exemplos do enunciado dão Salut e Segmentation fault: testa os dois.
  • A saída acaba com quebra de linha, como a do bc.
