ex00 display_file

Cria um programa ft_display_file que mostra na saída padrão o conteúdo do ficheiro passado como argumento, e só isso.

mostrar soluçãoesconder solução

Passo a passo

  1. open devolve um descritor (um número) ou -1 se falhar.
  2. read(fd, buf, tamanho) enche o array e devolve quantos bytes leu: 0 no fim do ficheiro, -1 em caso de erro.
  3. Lê-se e escreve-se aos bocados até o read devolver 0. Assim funciona com ficheiros de qualquer tamanho com um array fixo.
  4. Se o open ou um read falhar, a mensagem Cannot read file. vai para o descritor 2.
  5. O Makefile compila o .c e cria o executável; fclean apaga os dois.

Erros comuns

  • Ler o ficheiro todo de uma vez para um array de tamanho fixo: ficheiros grandes ficam cortados.
  • Escrever as mensagens de erro na saída normal.
  • Escrever buf inteiro em vez dos n bytes lidos.

Casos limite que a moulinette testa

  • Uma pasta como argumento: o open funciona mas o read falha, e tem de aparecer Cannot read file.
  • Ficheiros vazios e ficheiros maiores do que o array.

ex01 cat

Cria um programa ft_cat que faz o mesmo que o comando cat do sistema. Não precisas de tratar opções.

mostrar soluçãoesconder solução

Passo a passo

  1. Sem argumentos, o cat copia a entrada padrão (descritor 0). O argumento - também quer dizer entrada padrão.
  2. Cada ficheiro é aberto, copiado aos bocados com read/write e fechado.
  3. Quando um ficheiro falha, a mensagem segue o formato do cat: ft_cat: nome: motivo. O motivo vem do errno através do strerror, e o nome do programa do basename(argv[0]).
  4. Um erro não pára o programa: passa ao ficheiro seguinte e, no fim, devolve 1.
  5. O array tem 29696 bytes (29 KB), abaixo do limite.

Erros comuns

  • Parar no primeiro ficheiro com erro.
  • Escrever a mensagem fixa No such file or directory para todos os erros: uma pasta dá Is a directory.
  • Usar um array maior do que 30 KB.

Casos limite que a moulinette testa

  • Vários ficheiros seguidos, ficheiros inexistentes no meio, pastas, - e a entrada padrão.
  • Ficheiros binários grandes têm de ficar iguais byte a byte.

ex02 tail

Cria um programa ft_tail que faz o mesmo que o comando tail do sistema.

mostrar soluçãoesconder solução

Passo a passo

  1. -c N mostra os últimos N bytes. Aceita-se -c N e -cN.
  2. Não se sabe o tamanho de um ficheiro (ou da entrada padrão) antes de o ler, por isso lê-se tudo para memória num buffer que duplica de tamanho sempre que enche.
  3. Depois escreve-se a partir da posição tamanho - N (ou do início, se o ficheiro for mais pequeno).
  4. Com mais de um ficheiro, cada um leva o cabeçalho ==> nome <==, com uma linha vazia antes a partir do segundo, como o tail.
  5. Sem ficheiros, lê-se a entrada padrão. Os erros seguem o formato ft_tail: nome: motivo.

Erros comuns

  • Ler o ficheiro todo de uma vez com um tamanho fixo.
  • Esquecer os cabeçalhos com vários ficheiros.
  • Não libertar o buffer.

Casos limite que a moulinette testa

  • -c 0, N maior do que o ficheiro, vários ficheiros, entrada padrão.
  • O tail do macOS e o do Linux escrevem as mensagens de erro de forma diferente; testa no sistema da 42.

ex03 hexdump

Cria um programa ft_hexdump que faz o mesmo que o comando hexdump do sistema, sem redirecionamentos.

mostrar soluçãoesconder solução

Passo a passo

  1. Formato de cada linha: deslocamento com 8 algarismos, dois espaços, 16 bytes em hexadecimal (xx cada, com um espaço extra a meio), um espaço, e os caracteres entre | (ponto para os não imprimíveis).
  2. Todos os ficheiros são lidos como se fossem um só: uma linha pode começar num ficheiro e acabar no seguinte, e o deslocamento continua a contar.
  3. Linhas de 16 bytes iguais à anterior não se repetem: aparece um * na primeira e as outras são omitidas.
  4. No fim escreve-se o deslocamento total. Se não houver nenhum byte, não se escreve nada.
  5. Para caber na Norma, o estado (buffer, ficheiro atual, linha atual e anterior) vai numa estrutura, e o código divide-se em três ficheiros: leitura, escrita e main.

Erros comuns

  • Recomeçar o deslocamento em cada ficheiro.
  • Esquecer o * das linhas repetidas.
  • Errar o número de espaços na última linha, desalinhando a coluna |…|.
  • Escrever o deslocamento final quando a entrada está vazia.

Casos limite que a moulinette testa

  • Compara com diff <(./ft_hexdump -C f) <(hexdump -C f): ficheiros vazios, só com zeros, com tamanho múltiplo de 16 e não múltiplo, vários ficheiros e entrada padrão.
  • Um ficheiro inexistente no meio: mostra o erro e continua com os outros.
