ex01 ft_map

Cria a função ft_map, que aplica uma função a todos os elementos de um array de inteiros (por ordem) e devolve um array novo com os resultados.

mostrar soluçãoesconder solução

Passo a passo

  1. Reserva-se um array novo com length inteiros.
  2. Cada posição i recebe f(tab[i]). O array original não muda.

Erros comuns

  • Escrever os resultados no array original.
  • Esquecer o sizeof(int) no malloc.

Casos limite que a moulinette testa

  • O array original tem de ficar igual.

ex02 ft_any

Cria uma função ft_any que devolve 1 se, passado à função f, pelo menos um elemento do array der algo diferente de 0. Caso contrário, devolve 0.

mostrar soluçãoesconder solução

Passo a passo

  1. Percorre-se o array até ao ponteiro nulo.
  2. Logo que f devolva algo diferente de 0, devolve-se 1 sem testar os restantes.

Erros comuns

  • Comparar com 1 em vez de 0: f pode devolver qualquer valor diferente de 0.

Casos limite que a moulinette testa

  • Array vazio (só o ponteiro nulo) devolve 0.

ex04 ft_is_sort

Cria uma função ft_is_sort que devolve 1 se o array estiver ordenado e 0 se não estiver.

mostrar soluçãoesconder solução

Passo a passo

  1. «Ordenado» vale para as duas ordens: crescente e decrescente.
  2. Verificam-se as duas ao mesmo tempo. Um par com f > 0 estraga a crescente; um par com f < 0 estraga a decrescente.
  3. Se alguma das duas sobreviver, está ordenado.

Erros comuns

  • Só testar a ordem crescente: 9 4 4 -1 tem de dar 1.

Casos limite que a moulinette testa

  • Arrays com todos os valores iguais, com 0 ou 1 elemento: estão ordenados.

ex05 do-op

Cria um programa chamado do-op, que é executado com três argumentos: do-op valor1 operador valor2.

mostrar soluçãoesconder solução

Passo a passo

  1. Os números são lidos com o ft_atoi do C04 (espaços, vários sinais, algarismos). Por isso 42amis dá 42, --+-20toto12 dá -20 e toto3 dá 0.
  2. Há uma função por operação e um array ops com as cinco, pela mesma ordem da string "+-/*%". Encontrado o símbolo na posição i, o resultado é ops[i](a, b).
  3. O typedef int (*t_op)(int, int); dá um nome ao tipo «ponteiro para função», o que torna a declaração do array legível.
  4. O operador tem de ser exatamente um carácter: plus ou ++ são inválidos e mostram 0.
  5. A divisão e o resto por zero são verificados antes de calcular. Todas as saídas terminam com quebra de linha.

Erros comuns

  • Usar uma cadeia de if em vez do array de ponteiros para funções: o enunciado pede o array.
  • Aceitar só o primeiro carácter do operador (p de plus).
  • Mostrar alguma coisa com o número errado de argumentos.
  • Esquecer o Makefile: a moulinette corre make.

Casos limite que a moulinette testa

  • Todos os testes do exemplo, com a quebra de linha final.
  • ./do-op 1 + 2 3 (4 argumentos) não mostra nada.

ex06 ft_sort_string_tab

Cria a função ft_sort_string_tab, que ordena as strings de tab pela ordem ASCII.

mostrar soluçãoesconder solução

Passo a passo

  1. Ordenação por bolha com ft_strcmp, até ao ponteiro nulo.
  2. Trocam-se os ponteiros; o conteúdo das strings não muda.

Erros comuns

  • Copiar o conteúdo das strings em vez de trocar os ponteiros.
  • Ler tab[i + 1] depois do ponteiro nulo.

Casos limite que a moulinette testa

  • Array vazio ou com um só elemento; strings repetidas ou vazias.

ex07 ft_advanced_sort_string_tab

Cria a função ft_advanced_sort_string_tab, que ordena as strings de tab conforme o resultado da função passada como argumento.

mostrar soluçãoesconder solução

Passo a passo

  1. É o exercício anterior com cmp no lugar de ft_strcmp: se cmp(a, b) > 0, a deve ficar depois de b.

Erros comuns

  • Interpretar o sinal de cmp ao contrário.

Casos limite que a moulinette testa

  • Testam com comparações diferentes: por tamanho, por ordem inversa.
