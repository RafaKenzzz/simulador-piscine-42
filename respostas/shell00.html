ex00 z

Cria um ficheiro chamado z que, quando lido com cat, mostra Z seguido de uma quebra de linha.

mostrar soluçãoesconder solução

Passo a passo

  1. echo "Z" > z escreve Z e acrescenta a quebra de linha (o echo põe sempre uma no fim).
  2. O > cria o ficheiro, ou apaga o que lá estava e escreve por cima.
  3. Confirma com cat -e z: tem de aparecer Z$. O $ marca o fim da linha.

Erros comuns

  • Usar printf Z, que não acrescenta a quebra de linha.
  • Escrever o Z com um editor que não guarda a quebra de linha final.
  • Deixar um espaço depois do Z.

Casos limite que a moulinette testa

  • O ficheiro tem exatamente 2 bytes: Z e \n. Confirma com wc -c z.

ex01 testShell00

Cria um ficheiro testShell00 cujo ls -l fique assim (a linha total não conta):

mostrar soluçãoesconder solução

Passo a passo

  1. printf '%040d' 0 escreve o número 0 com 40 algarismos (quarenta zeros), sem quebra de linha: exatamente 40 bytes.
  2. touch -t 06012342 muda a data de modificação para 1 de junho às 23:42 (formato MMDDhhmm; o ano é o atual).
  3. As permissões em octal: r-- = 4, r-x = 5, r-x = 5, por isso chmod 455.
  4. O touch vem antes do chmod: assim nunca tentas alterar um ficheiro sem permissão de escrita.
  5. Por fim, tar -cf cria o arquivo. Entregas só testShell00.tar.

Erros comuns

  • Errar o tamanho: um echo acrescenta um \n e passa a 41 bytes.
  • Fazer o tar antes de acertar as permissões e a data. O arquivo guarda o estado no momento em que é criado.
  • Confundir a ordem dos três grupos de permissões: dono, grupo e outros.

Casos limite que a moulinette testa

  • Quem corrige extrai o arquivo com tar -xf e corre ls -l. As permissões, o tamanho e a data têm de bater certo.

ex02 Oh yeah, mooore...

Cria os ficheiros e pastas necessários para que o ls -l na tua pasta mostre:

mostrar soluçãoesconder solução

Passo a passo

  1. O 2 em test3 e test5 é o número de ligações: os dois são o mesmo ficheiro, ligados com ln test3 test5 (ligação física).
  2. test6 é uma ligação simbólica: ln -s test0 test6. O tamanho 5 é o comprimento do texto test0.
  3. Os tamanhos saem do conteúdo: printf '1234' dá 4 bytes, printf '1' dá 1, printf '12' dá 2.
  4. Permissões em octal: rwx--xr-x = 715, rwx--xr-- = 714, r-x---r-- = 504, r-----r-- = 404, rw-r----x = 641.
  5. As datas acertam-se com touch -t MMDDhhmm. Na ligação simbólica usa touch -h, senão mudas a data de test0.
  6. Como test3 e test5 são o mesmo ficheiro, basta mudar a data de um.

Erros comuns

  • Copiar test3 para test5 em vez de criar uma ligação física: ficam com 1 ligação cada.
  • Mudar as datas antes de acabar de criar tudo. Criar um ficheiro dentro de uma pasta muda a data da pasta.
  • Esquecer o -h no touch da ligação simbólica.

Casos limite que a moulinette testa

  • No macOS, chmod -h 755 test6 muda as permissões da ligação simbólica. No Linux não é possível: aparece sempre lrwxrwxrwx.
  • Quem corrige extrai o exo2.tar e compara o ls -l linha a linha, incluindo o número de ligações.

ex03 Connect me!

Garante que tens um bilhete Kerberos válido (não expirado). Se não tiveres, pede um.

mostrar soluçãoesconder solução

Passo a passo

  1. kinit pede um bilhete Kerberos (normalmente com o teu login e a palavra-passe da intra).
  2. klist mostra os bilhetes que tens. O > envia essa saída para klist.txt.
  3. Confirma com cat klist.txt que aparece pelo menos um bilhete com data de validade.

Erros comuns

  • Entregar um klist.txt vazio porque o kinit falhou.
  • Escrever o ficheiro à mão em vez de usar a saída do klist.

Casos limite que a moulinette testa

  • O conteúdo depende da tua máquina e do campus. Quem corrige verifica que é a saída real do klist.

ex04 midLS

Num ficheiro midLS, escreve a linha de comando que lista os ficheiros e pastas da pasta atual:

mostrar soluçãoesconder solução

Passo a passo

  1. -m separa os nomes por vírgulas.
  2. -p acrescenta uma / ao nome das pastas.
  3. -t ordena por data, da mais recente para a mais antiga.
  4. No macOS, -U faz o -t usar a data de criação em vez da de modificação.
  5. O ls já esconde os ficheiros que começam por ponto, por isso não é preciso mais nada.

Erros comuns

  • Usar só ls -mpt: ordena pela data de modificação, não de criação.
  • Acrescentar -a ou -A, que mostram os ficheiros escondidos.
  • Escrever ls -U no Linux: aí -U quer dizer «não ordenar», não «data de criação».

Casos limite que a moulinette testa

  • Nas máquinas macOS da 42 usa ls -mpUt. Num Linux com coreutils recentes o equivalente é ls -mpt --time=birth.
  • Uma pasta vazia não mostra nada; uma pasta com um só ficheiro não tem vírgulas.

ex05 GiT commit

Cria um script de shell que mostra os identificadores (hash completo) dos últimos 5 commits do teu repositório git, um por linha.

mostrar soluçãoesconder solução

Passo a passo

  1. git log mostra o histórico de commits, do mais recente para o mais antigo.
  2. -5 limita a 5 commits.
  3. --format=%H mostra só o hash completo de cada commit, um por linha.

Erros comuns

  • Usar --oneline ou %h: mostram o hash abreviado (7 caracteres).
  • Usar git log | head -5: corta as primeiras 5 linhas do log completo, não 5 commits.

Casos limite que a moulinette testa

  • A moulinette corre o script no repositório dela, por isso não ponhas hashes fixos no ficheiro.
  • Num repositório com menos de 5 commits mostra só os que existem.

ex06 gitignore

Escreve um script de shell curto que lista todos os ficheiros existentes que o teu repositório git ignora (por causa do .gitignore).

mostrar soluçãoesconder solução

Passo a passo

  1. git ls-files lista ficheiros do repositório.
  2. --others mostra os ficheiros que o git não segue.
  3. --ignored fica só com os que estão a ser ignorados.
  4. --exclude-standard aplica as regras habituais: .gitignore, .git/info/exclude e o ficheiro global.

Erros comuns

  • Fazer cat .gitignore: mostra as regras, não os ficheiros que existem e são ignorados.
  • Esquecer o --exclude-standard: sem regras, nada é considerado ignorado.

Casos limite que a moulinette testa

  • Testam no repositório deles: o script tem de funcionar a partir de qualquer pasta do repositório.

ex07 diff

Recebes um ficheiro a (o texto do início da Guerra das Estrelas) e o resultado de diff a b > sw.diff.

mostrar soluçãoesconder solução

Passo a passo

  1. O sw.diff descreve as diferenças entre a e b. O patch faz o caminho inverso: aplica essas diferenças a a.
  2. patch -o b a < sw.diff lê o diff, aplica-o a a e escreve o resultado em b, sem alterar a.
  3. Para confirmar, gera um diff novo e compara-o com o original: diff a b > teste.diff e diff teste.diff sw.diff não deve mostrar nada.

Erros comuns

  • Correr patch a sw.diff: altera o próprio a em vez de criar b.
  • Copiar o texto de b à mão do PDF: perdes espaços e quebras de linha.

Casos limite que a moulinette testa

  • O b tem de ser igual byte a byte, incluindo linhas vazias e a última quebra de linha.

ex08 clean

Num ficheiro clean, escreve a linha de comando que procura, na pasta atual e em todas as subpastas, os ficheiros cujo nome:

mostrar soluçãoesconder solução

Passo a passo

  1. find . percorre a pasta atual e todas as subpastas.
  2. -type f fica só com ficheiros (não apaga pastas com nomes parecidos).
  3. \( -name '*~' -o -name '#*#' \) junta as duas condições com um «ou». Os parênteses têm de estar escapados para a shell não os interpretar.
  4. -print mostra o caminho e -delete apaga. Tudo dentro de um único find.

Erros comuns

  • Esquecer as aspas em '*~': a shell expande o padrão antes de o find o ver.
  • Esquecer os parênteses: sem eles, o -print -delete só se aplica à segunda condição.
  • Usar rm com ; ou &&, que o enunciado proíbe.

Casos limite que a moulinette testa

  • Um ficheiro #ficheiro (só com # no início) fica: tem de começar e acabar em #.
  • Ficheiros escondidos também são procurados: .ficheiro~ é apagado.

ex09 Illusions, not tricks, Michael...

Cria um ficheiro mágico ft_magic, no formato do comando file, que detete ficheiros do tipo «42 file»: ficheiros com a string 42 no 42.º byte.

mostrar soluçãoesconder solução

Passo a passo

  1. Cada linha de um ficheiro mágico tem quatro colunas: posição, tipo, valor a procurar e mensagem.
  2. A posição conta a partir de 0, por isso o 42.º byte está na posição 41.
  3. string 42 procura os caracteres 4 e 2 a partir dessa posição.
  4. A mensagem 42 file é o que o file mostra quando encontra o padrão.
  5. Testa com file -m ft_magic ficheiro.

Erros comuns

  • Usar a posição 42: isso é o 43.º byte.
  • Separar as colunas de forma inconsistente. Usa tabs ou espaços, mas cada coluna tem de estar separada.

Casos limite que a moulinette testa

  • Um ficheiro com 42 noutra posição não é detetado.
  • Um ficheiro com menos de 43 bytes não pode ter 42 na posição certa.
