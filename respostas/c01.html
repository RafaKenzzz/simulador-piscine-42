ex00 ft_ft

Cria uma função que recebe um ponteiro para int e põe o valor 42 nesse int.

mostrar soluçãoesconder solução

Passo a passo

  1. nbr é um endereço. *nbr é o int que está nesse endereço.
  2. Escrever em *nbr muda a variável de quem chamou a função, por exemplo ft_ft(&n) muda n.

Erros comuns

  • Escrever nbr = 42: muda o ponteiro local e o compilador recusa (atribuir um int a um ponteiro).

Casos limite que a moulinette testa

  • O teste faz int n = 0; ft_ft(&n); e verifica que n == 42.

ex01 ft_ultimate_ft

Cria uma função que recebe um ponteiro para ponteiro para ponteiro… (nove vezes) para int e põe o valor 42 nesse int.

mostrar soluçãoesconder solução

Passo a passo

  1. Cada * desfaz um nível de endereço. Com nove * na declaração, são precisos nove * para chegar ao int.
  2. *********nbr = 42; resolve o exercício numa linha.

Erros comuns

  • Contar mal os asteriscos: com oito, escreves num ponteiro e o compilador recusa.

Casos limite que a moulinette testa

  • O teste cria a cadeia de 9 ponteiros e confirma o valor no int do fundo.

ex02 ft_swap

Cria uma função que troca os valores de dois inteiros cujos endereços são passados como parâmetros.

mostrar soluçãoesconder solução

Passo a passo

  1. Guarda-se *a numa variável temporária, copia-se *b para *a e o valor guardado para *b.
  2. Sem a variável temporária, o valor de *a perdia-se quando era escrito por cima.

Erros comuns

  • Trocar os ponteiros locais (tmp = a; a = b; b = tmp;): não muda nada fora da função.
  • Fazer *a = *b; *b = *a;: os dois ficam com o valor de *b.

Casos limite que a moulinette testa

  • Testam valores negativos e iguais.

ex03 ft_div_mod

Cria uma função que divide a por b, guarda o resultado no int apontado por div e o resto da divisão no int apontado por mod.

mostrar soluçãoesconder solução

Passo a passo

  1. / entre inteiros dá a divisão inteira (sem casas decimais) e % dá o resto.
  2. Os resultados são escritos nos endereços recebidos: *div e *mod.

Erros comuns

  • Atribuir a div e mod em vez de *div e *mod.

Casos limite que a moulinette testa

  • Com negativos, C arredonda para zero: -7 / 2 dá -3 e -7 % 2 dá -1.
  • A divisão por zero não é testada (o resultado é indefinido).

ex04 ft_ultimate_div_mod

Cria uma função que divide a por b. O resultado fica no int apontado por a e o resto no int apontado por b.

mostrar soluçãoesconder solução

Passo a passo

  1. O problema é a ordem: depois de escrever o resultado em *a, o valor original de *a desaparece, mas ainda é preciso para o resto.
  2. Por isso guarda-se primeiro o valor original numa variável e calcula-se tudo a partir dela.

Erros comuns

  • Escrever *a = *a / *b; *b = *a % *b;: o resto é calculado com o resultado da divisão, não com o valor original.

Casos limite que a moulinette testa

  • 42 e 10 têm de dar 4 e 2.

ex05 ft_putstr

Cria uma função que mostra uma string de caracteres na saída padrão.

mostrar soluçãoesconder solução

Passo a passo

  1. Uma string em C é uma sequência de caracteres terminada por '\0'.
  2. Escreve-se um carácter de cada vez e avança-se o ponteiro até ao '\0'.

Erros comuns

  • Escrever também o '\0'.
  • Acrescentar uma quebra de linha.

Casos limite que a moulinette testa

  • Uma string vazia não mostra nada.

ex07 ft_rev_int_tab

Cria uma função que inverte um array de inteiros: o primeiro passa a último, e assim por diante.

mostrar soluçãoesconder solução

Passo a passo

  1. Troca-se o elemento i com o size - 1 - i.
  2. Pára-se a meio (i < size / 2): se o ciclo fosse até ao fim, cada par seria trocado duas vezes e o array voltava ao início.

Erros comuns

  • Ir até size: o array fica igual ao original.
  • Errar o índice do fim (size - i em vez de size - 1 - i) e ler fora do array.

Casos limite que a moulinette testa

  • Arrays com tamanho par e ímpar; com 1 elemento ou 0, nada muda.

ex08 ft_sort_int_tab

Cria uma função que ordena um array de inteiros por ordem crescente.

mostrar soluçãoesconder solução

Passo a passo

  1. Ordenação por bolha: compara-se cada elemento com o seguinte e trocam-se se estiverem fora de ordem.
  2. Depois de uma troca, recomeça-se do início (i = 0). Quando se chega ao fim sem trocas, está ordenado.
  3. É lento para arrays grandes, mas curto, fácil de acertar e cabe nas 25 linhas.

Erros comuns

  • Ir até i < size e comparar tab[i] com tab[size], fora do array.
  • Esquecer os valores repetidos: têm de ficar todos.

Casos limite que a moulinette testa

  • Negativos, repetidos, INT_MIN e INT_MAX, array já ordenado e array com 0 ou 1 elementos.
